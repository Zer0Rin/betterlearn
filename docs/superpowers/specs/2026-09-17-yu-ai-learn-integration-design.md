- Claude 的改动已实现跨服务读取知识库正文，尚未完成代码迁入、统一界面或统一启动。

## 方案比较

1. **推荐：同仓库、统一界面，由 Host 管理独立练习服务。** 复用已改好的服务和 UI，保留 MySQL/Chroma。迁移风险较小，但仍需 MySQL 和练习服务的模型配置。
2. 全部重写进现有 Python Core，并统一到 SQLite 和 DSH 模型调用。最终依赖更少，但同时涉及存储、任务、认证和模型编排重写，回归范围明显更大。
3. 只把两个应用放进同一仓库，继续保留两个界面。不满足用户已选定的使用方式。

## 推荐设计

### 代码归属

- 在 `services/quiz/` 迁入 Python 后端、依赖声明和相关测试，使用独立 Python 环境，避免与现有 Core 依赖冲突。
- 在 `src/client/quiz/` 迁入并适配出题、答题、复盘、知识库及练习历史 UI；纳入 BetterLearn 的现有构建，不再要求用户启动另一套 Vite 网页。
- 在 `src/product/` 增加练习服务生命周期管理和明确的业务接口适配。
- 迁入相关运行说明、测试及原项目许可证和来源说明。构建产物、虚拟环境、密钥、上传原件和数据库不作为源码复制进 Git。
- 原鱼皮目录保留作为迁移前参考；验收不依赖它，不删除原目录。

### 使用流程

- BetterLearn 增加“知识库”和“练习”入口，与已有知识提取、学习书入口共存。
- 知识库支持上传、处理状态、删除，以及“提取到学习书”和“基于文档练习”两条路径。
- 练习支持现有主题/文本/网址输入、文档来源、题数、难度及配图设置。
- 保留异步出题状态、三种题型、答案解析、刷新恢复、复盘和练习历史。
- 本次不新增“学习书反向出题”或将练习成绩写入课程掌握度；二者属于现有功能之外的新契约。

### 服务与认证

- bl4dsh 安装/升级流程包含练习服务代码和依赖；统一启动时由 Host 管理服务启动、就绪检查和退出回收。
- 练习服务监听回环地址，端口由配置管理；端口占用、数据库不可用和服务启动失败返回可操作的错误。
- 浏览器只访问 bl4dsh 同源业务接口，Host 转发明确允许的请求，保持现有请求来源校验。
- Host 管理本机练习身份及凭据获取/续期，不要求用户从另一网页手工复制 JWT。
- Claude 已有的知识库读取适配器改为读取仓库内受管理的服务；正确映射正文接口错误，当前文档声称 404 而实际后端返回 400 的差异需在实施时统一。

### 存储、模型与安装

- 保留 BetterLearn SQLite 与练习 MySQL/Chroma 各自的存储职责，界面统一不等于立即统一数据库。
- MySQL 仍是运行依赖，安装文档和环境检查必须明确说明；统一启动不代表可以省略数据库准备。
- 上传文件、向量和配置使用 bl4dsh 管理的数据路径，不写入源码目录。
- 现有模型、检索和配图配置继续由练习服务使用，通过统一安装配置接入；BetterLearn 原有提取仍使用 DSH 模型选择。此次不承诺两套模型配置自动一致。
- 现有本地文档和历史数据如需带入，应备份后执行明确的数据迁移步骤；不在复制源码时静默移动或覆盖。
