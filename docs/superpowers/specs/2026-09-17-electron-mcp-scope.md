# BetterLearn Electron 与通用插件范围

日期：2026-09-17

状态：产品方向经用户确认。Electron 第一阶段已实现，验收见 `docs/desktop-verification.md`；MCP 业务接口与 stdio 连接程序已实现（见 `docs/mcp.md`）；Codex／Claude Code 包装已完成本机安装与协议验证（见 `docs/plugins.md`），宿主模型的自然语言会话未在本轮验收。本文记录整体范围，不是全阶段交付完成报告。

## 已确认的职责

BetterLearn 是独立的本机单人学习应用。Electron 提供桌面入口，复用现有独立 Web 的页面、业务服务与数据存储。输入资料后点击生成，由 BetterLearn 调用用户在自身设置中配置的模型 API，返回题目后开始答题，无需打开 Codex 或 Claude Code。

文本生成、向量化、图片和联网搜索按各自配置调用服务。宿主 AI 的模型、搜索工具和订阅额度不是 BetterLearn 运行的必要条件。缺少所需配置时返回明确错误，不自动改用宿主能力。

Codex、Claude Code 等通过 MCP 访问 BetterLearn。宿主可以查询资料和历史，也可以请求 BetterLearn 启动生成任务；生成仍由 BetterLearn 配置的 API 完成。宿主读取结果后的解释不替代 BetterLearn 自己的生成流程。

API Key 留在 BetterLearn 后端管理，不作为 MCP 工具参数要求宿主提供，也不通过工具结果、错误消息或日志返回。设置界面可以显示配置状态。

## 数据流

桌面使用：用户输入 → Electron 界面 → BetterLearn 业务服务 → 配置的 API → 结果校验与保存 → 展示选择题。

插件使用：用户向宿主发出指令 → MCP 工具 → 同一业务服务 → 配置的 API → 结果校验与保存 → 宿主查询任务与结果。

读取历史、查询状态、查看已有题目不得触发新的生成。耗时生成采用启动任务、查询状态、读取结果的接口；重复查询不得产生重复收费调用。工具的具体名称和字段在接口设计阶段确定。

## 当前基础

- `src/standalone/` 已提供独立页面、应用服务、配置、启动和维护入口。
- `src/standalone/config.ts` 已管理文本、Embedding、图片及搜索配置，并向界面返回隐藏密钥的配置视图。
- Python Core 与练习服务已有本地数据存储；继续复用其校验、任务状态和恢复规则。
- 本次只确认新方向，不承诺现有任务接口已经满足 MCP 所需的重试与幂等要求。

## 分阶段落实

1. Electron 桌面交付：先处理启动、首次运行依赖准备、数据目录、单实例、退出清理和桌面打包，保持现有 Web 入口可用。Python 环境的分发方式需要在桌面实施方案中明确，不能将浏览器窗口包装视为安装交付完成。
2. MCP 业务接口：复用应用服务，提供受限的读取与生成操作；与桌面共用数据目录时，由同一业务服务持有数据锁，不能为每个宿主各启动一套写入服务。实施方案需明确本地连接认证和服务生命周期。
3. 宿主插件包装：共用 MCP 实现，分别提供 Codex／Claude Code 安装配置及使用说明。以实际安装和调用验证兼容性，不假定所有宿主的插件安装格式相同。

## 验收要求

- 不安装 Codex、Claude Code 或 DSH，也能启动桌面应用并使用配置的 API 生成、答题和查看历史。
- 用假供应商记录请求，证明 Electron 和 MCP 两个入口均调用 BetterLearn 配置的服务。
- 模型或搜索配置缺失时明确失败，不请求宿主模型、搜索工具或账号授权。
- API Key 不出现在渲染进程的公开配置、MCP 返回值和错误输出中。
- 查询任务与历史不重复生成；重复启动请求的处理需有明确约定和验证。
- MCP 生成的结果与桌面使用同一份业务数据，能够在 Electron 中打开并作答。
- 应用退出、重启及宿主断连的行为明确，不绕过现有数据锁，也不默默重发收费请求。

## 本期排除

不接入 Codex App Server、Claude Agent SDK 或宿主账号登录；不读取宿主凭证；不提供订阅额度转接；不接收宿主生成的题目作为本期标准生成路径；不依赖宿主搜索替代自身搜索 API；不新增多用户或公网部署能力。

原独立 Web 设计中“本次不实现 Electron”描述的是已完成的 Web 阶段。本文确认 Electron 为后续阶段，不改变旧阶段的验收事实。
