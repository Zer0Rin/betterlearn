# BetterLearn 本地单人独立 Web 版设计

日期：2026-09-17

状态：用户已确认产品方向、Web 优先于 Electron、单人使用、练习服务改用 SQLite；本文具体设计待审阅。

## 1. 目标与边界

BetterLearn 独立运行于本机，在浏览器提供完整学习工作台。安装、构建、启动、模型调用和业务流程均不要求 DSH。后续 Electron 复用同一套页面、应用接口和数据目录，仅补充桌面生命周期、系统文件交互与分发能力。

首版保留资料导入、知识库、候选提取、证据审核、知识点、学习书、课程进度、出题、答题、复盘、历史与个人学习统计。无需注册登录，内部使用固定本机学习者身份；不是多用户服务器产品。

本次不实现 Electron、不适配新版 DSH、不迁移原正式数据、不合并课程掌握度与练习成绩。原迁入版本以提交 d099d11 为基线，实施使用单独分支。DSH 集成代码隔离为可选适配部分，不要求维持本次改造后旧插件的安装兼容性；原基线可独立保留。

## 2. 方案选择

采用独立 Web 应用加明确适配边界。只抽象核心仍无法脱离 DSH；先做 Electron 会提前引入打包与平台维护，因此不采用这两条路径作为首阶段。

保留 TypeScript 应用服务、Python Core 和练习服务的已有职责，避免将脱离宿主、替换数据库与重写后端合并成一次重构。两个业务数据库均使用 SQLite，暂不强行合库。

## 3. 运行架构

```text
浏览器中的 BetterLearn 完整页面
  └─ 本机应用服务（静态页面、HTTP API、SSE、配置）
       ├─ 模型适配层：独立解析配置和执行生成
       ├─ Python Core：提取状态、证据、审核、知识点、学习书
       │    └─ Core SQLite
       └─ Python 练习服务：知识库、出题、复盘、历史
            ├─ Quiz SQLite
            ├─ Chroma
            └─ 上传文件与图片
```

应用服务统一启动和停止子进程，检测就绪、端口冲突和退出状态。默认只监听回环地址，浏览器通过同源接口访问。无登录页面不等于开放接口：保留 Host/Origin 校验，私有子服务凭证和模型密钥不得发送到浏览器或日志。

从 DSH 插件装配中拆出应用操作层；路由注册、子进程启动、模型配置解析、结构化生成、会话来源均依赖自有接口。独立入口及其依赖图不得导入 DSH 模块，独立构建与安装也不能依靠 DSH peer dependencies。DSH 适配代码及测试与独立产品构建隔离。

## 4. 页面与工作区

复用现有业务组件，外层改为完整页面，提供知识点/提取、学习空间、知识库、练习、历史与设置入口。去除必须存在 DSH 当前会话或浮窗才能使用的条件。

本机工作区拥有自己的稳定标识，刷新后恢复选中任务和答题进度；业务历史以服务端数据库为准。模型设置变化不触发重新提取。独立版不显示需要 DSH 的对话选择入口；文件、粘贴和知识库导入可完整使用，未来会话来源通过适配接口接入。

## 5. 模型与外部能力

统一设置入口管理文本模型连接（地址、密钥、模型名及已支持的能力选项），提取、课程相关生成、出题、复盘按用途引用连接；默认可共用一个文本连接。首版文本适配以 OpenAI 兼容接口为范围，不承诺任意供应商协议均可直接使用。具体协议能力与 SDK 选择在实施前查阅当前文档。

Embedding、图片生成和联网检索独立配置，首版复用现有已实现的供应商适配。未配置时明确提示受影响功能，其余页面和学习数据仍可使用。修改 embedding 模型不得静默复用不兼容向量，应阻止误用并提示重建需求。

提取任务冻结 provider、model 和适用参数，保留原 L1/L2/L3 规划、候选约束、精确证据定位、人工审核及调用次数预览。结构化输出仍由完整业务契约校验，供应商返回 JSON 不等于校验通过。重试和取消行为保持明确，刷新及恢复页面不得额外调用模型。

密钥仅保存在本机受限配置中；设置接口只返回掩码或已配置状态，保存支持保留/替换/清除。配置检查和涉及模型调用的连接测试区分展示。首版不实现自动供应商发现。

## 6. 数据与 SQLite 替换

统一数据根目录中保留 Core SQLite、Quiz SQLite、uploads、chroma 和私有配置。新安装创建空数据，不读取旧 DSH 或原教程环境。

练习服务替换 aiomysql 连接、MySQL DDL、占位符、时间函数及 upsert 等语法。保留文档和练习业务 ID、关系、索引、历史排序和 API 数据形状。使用显式事务与外键约束，验证重复复盘不会重复增加经验值，失败写入可回滚。配置数据库版本和升级入口，不用仅创建表的方式代替后续迁移。

内部固定学习者沿用原有 user_id 关联，不在本次改造中删除这些关系。首版没有 MySQL 服务或账号配置要求。

本地图片存储作为首版建议：生成图片保存到受管理数据目录，通过应用接口读取，COS 成为可选适配，不作为本机配图的必要条件。图片生成供应商仍可需要外部服务。实现时限制文件读取范围、下载大小和超时，外部图片下载遵循明确允许的服务来源。

整套备份覆盖两个 SQLite、上传文件、Chroma、本地图片及恢复所需配置；私有配置随备份保留时明确告知其中含密钥。采用停止写入并关闭相关存储后的一致副本方案，验证恢复到新目录。外部 COS 对象不隐式包含在本地备份中。

## 7. 错误与中断

缺少模型配置时应用仍可打开和读取已有数据；产生模型调用的操作给出明确设置入口。服务启动失败需说明失败组件，子进程日志脱敏。

保留现有 Core 的恢复语义。练习和文档后台任务在服务重启后，将无法继续执行的处理中状态转为明确的中断失败并允许用户显式重试；不自动再次发起收费调用，不承诺断点续跑。刷新页面和关闭页面不等同于服务崩溃，必须分别验证。

## 8. 实施顺序

1. 抽离宿主接口与应用装配，建立独立启动、静态页面和工作区入口。
2. 替换练习数据库为 SQLite，用真实临时 SQLite 验证仓库和事务语义。
3. 加入独立模型配置与执行适配，打通知识提取、审核和学习书。
4. 接入完整知识库与练习界面、设置页，以及本地图片存储。
5. 补全重启处理、独立安装/打包、整套备份恢复及端到端验收。

每步保留可运行的验证入口；正式数据迁移和 Electron 分别另立后续计划。

## 9. 验收条件

- 干净环境不安装 DSH、不启动 MySQL，能够安装并启动完整 Web 应用；所需 Node/Python 环境在说明中写清，首版不承诺 Electron 式自包含安装包。
- 文件/粘贴 → 预览 → 提取 → 证据审核 → 知识点 → 学习书 → 课程进度完整通过。
- 知识库上传 → 解析/向量化 → 正文预览 → 提取与审核完整通过。
- 知识库/主题输入 → 出题 → 答题 → 复盘 → 历史与统计完整通过；可选搜索和图片分别验收。
- 两个 SQLite 均持久化，应用重启后数据可读取；浏览器刷新恢复进度不产生额外模型调用。
- 取消、模型错误、无效结构化输出、存储失败、处理中退出与重复提交有对应验证。
- 临时真实 SQLite 测试覆盖外键、事务、唯一约束、JSON 和时间读写，不能只用 MySQL mock 改名证明替换成功。
- 整套备份恢复到独立目录后，知识点、课程、文档检索、练习历史和本地图片可用。
- 独立构建无 DSH 运行依赖；浏览器无密钥，业务页面不依赖 Electron API。
- 自动验收使用 fake provider；真实模型验收与自动测试分开记录，明确调用范围和费用条件。

## 10. 后续 Electron

Electron 主进程负责启动同一应用服务、管理窗口和退出、提供文件选择以及分发更新。业务计算与存储继续经应用接口完成，渲染页面不直接使用 Node 或数据库。Web 首版暂不承诺 Windows 分发；Electron 阶段另行验证 Python、向量库与各平台打包兼容性。
